ОБНОВЛЕНИЕ ПРОГРАММЫ ОДНОЙ КНОПКОЙ
Источник: https://github.com/PepDominator/pep-apps-releases

Первое обновление
Закрой прежнюю программу и один раз замени EXE в той же папке на эту сборку.
Исходники заменять не нужно. Папки профиля, BAT и загрузок не удаляй.
Дальше используй Настройки / Параметры → Обновления программы.

1. Проверь адрес PepDominator/pep-apps-releases. Можно вставить полную ссылку
   на другой публичный репозиторий и сохранить. Страница аккаунта не подходит.
2. Нажми Проверить обновления. Появится новая версия и описание изменений.
   Проверка по кнопке; фоновых проверок и отправки пользовательских данных нет.
3. Нажми Скачать обновление. Показываются размер и прогресс. Проверяются размер,
   SHA-256 от GitHub и формат Windows x64 EXE. До установки можно отменить.
4. Нажми Установить и перезапустить. Если есть активные/ожидающие загрузки,
   программа дождётся завершения всей текущей очереди, включая внешние консоли.
   Новые задачи пока можно добавлять; ожидание установки можно отменить.
5. Когда очередь завершена, программа ещё раз сохраняет настройки/рабочие данные,
   временно блокирует изменения, закрывает окно и заменяет текущий EXE.
6. Новая версия запускается автоматически. Будущие таймеры сохраняются и
   продолжают обслуживаться после старта. Программа должна оставаться открытой.

Что сохраняется
Обновление меняет только текущий EXE. AppData, планы, списки, комментарии, ключи,
профили, папки BAT и скачанные файлы не удаляются. Несохранённые команды/поля
перед установкой сохрани самостоятельно; секретные URL/ключи из незапущенной
формы StreamDesk ради обновления на диск не записываются.

Имя файла и ярлык
Текущий путь EXE сохраняется, чтобы ярлыки и Native Messaging не ломались.
Если EXE называется с прежним номером версии, имя останется прежним. Фактическая
версия видна внутри программы. Для постоянного пути можно один раз назвать EXE
FixtureStudio.exe / StreamDesk.exe и настроить ярлык/связь с расширением заново.

Резервная копия и откат
Рядом с основным EXE сохраняется имя.exe.previous.exe — только предыдущая версия.
При неудачной замене возвращается прежний EXE. Если новый интерфейс не подтвердил
старт, помощник восстанавливает предыдущую версию. До подтверждения старта
планировщики приостановлены, чтобы откат не остановил новую загрузку.
При ручном откате закрой программу, переименуй текущий EXE для сохранения,
а файл .previous.exe верни на его прежнее основное имя. Данные не удаляй.
Это откат EXE; совместимость форматов данных между далёкими версиями отдельно
не гарантируется. Перед крупными обновлениями можно сделать обычную резервную
копию данных через предусмотренные программой средства.

Если не получается
404 — проверь адрес и публичность репозитория; релиз должен быть опубликован.
403/429 — GitHub ограничил запросы, повтори позже. При сетевой ошибке проверь
интернет/VPN. Нехватка прав на папку проверяется до закрытия программы: выбери
для программы папку, доступную на запись, например внутри пользовательской.
Если SHA-256 не совпадает, EXE не применяется. Без digest от GitHub обновление
не устанавливается. Черновики, предварительные релизы и файлы другого приложения
пропускаются. Исходники и ZIP автоматически не исполняются.

Для следующей публикации
Добавляй в стабильный публичный GitHub Release EXE с точным именем:
FixtureStudio-X.Y.Z.exe / StreamDesk-X.Y.Z.exe. Версии независимы. Можно общий
релиз с обеими программами. В описании релиза напиши изменения; SHA-256
формируется GitHub при загрузке. Предварительный релиз можно проверить workflow
Windows updater verification, затем сделать стабильным. Скачивать обновление
из чата программа не умеет: будущие сборки нужно публиковать в этом репозитории.
